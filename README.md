# 악보 편집

오선·타브 악보와 PDF 악보를 만들고 고치고, 연주할 때는 콘티대로 눌러서 넘기는 웹 앱이에요. 로그인하고 들어가면 처음 화면이 두 부분으로 나뉘어요.

| 처음 화면 | 들어 있는 것 |
|---|---|
| **악보 편집** | 프로젝트 만들기·연동하기, 오선·타브 악보 만들기(녹음·파일 → 악보, 고치기, 형광펜 구간 표시), PDF 악보(가리기·음표·코드 고치기, 표시) |
| **악보 실행** | PDF·사진 악보를 콘티(곡 순서)대로 넘기며 연주해요. 반 쪽 넘김·두 쪽·이어 보기, 반복 점프 링크, 메트로놈, 반주 음원, 공연 잠금, 밤 모드. 프로젝트에서는 주최자가 넘기면 모두 함께 넘어가요. |

처음 화면 아래의 **내 악보함**에는 만든 악보가 모두 모여요(오선·타브 악보, PDF·사진 파일). 이 기기(브라우저)에 저장돼요.
휴대폰 홈 화면에 아이콘으로 설치할 수 있고, 한 번 열면 인터넷이 없어도 (혼자 쓰기 기능은) 켜져요.

코드 사전·키별 코드·스케일 도감·리프 만들기는 따로 나뉜 **악기 코드 도감** 앱에 있어요.
녹음 분석에서 알아낸 코드 진행은 “코드 진행 복사하기”로 복사해서 악기 코드 도감 앱의 “리프 만들기”에 붙여 넣으면 돼요.

## 올리는 방법 (GitHub Pages, 무료)

1. 이 폴더의 파일을 **전부** GitHub 저장소에 올려요. (저장소 → Add file → Upload files → 파일 전체 선택 → Commit changes)
   악기 코드 도감 앱과 같은 저장소에 올린다면 폴더를 나눠요(예: `score/` 폴더에 이 앱). 그러면 주소는 `https://내아이디.github.io/저장소이름/score/`가 돼요.
   ⚠️ 저장소의 `firebase-config.js`를 이미 채워 두었다면 **이 파일만 빼고** 올리세요. 빈 파일로 덮어쓰면 로그인 화면이 사라져요. (덮어썼다면 아래 5번처럼 다시 채우면 돼요)
2. Settings → Pages → Source: **Deploy from a branch**, Branch: **main / (root)** → Save
3. 2~3분 뒤 `https://내아이디.github.io/저장소이름/` 으로 열려요.

`firebase-config.js`가 비어 있으면 처음 화면에서 “시작하기 (혼자 쓰기)”만 나오고, 모든 연습 기능을 혼자 쓸 수 있어요.
로그인과 공동 프로젝트를 켜려면 아래 “함께하기(로그인) 켜기”를 한 번만 해 주면 돼요.

## 함께하기(로그인) 켜기 — Firebase 무료 요금제(Spark)로 충분해요

로그인 정보와 공유 악보는 Google의 **Firebase**에 저장돼요. 처음 한 번만 설정하면 돼요. (구글 계정 필요, 카드 등록 필요 없음)
이전의 통합 앱(악기 코드 도감)에서 이미 설정했다면 그 `firebase-config.js`를 그대로 쓰면 돼요. 같은 계정·프로젝트가 이어져요.

1. **프로젝트 만들기**: <https://console.firebase.google.com> → 프로젝트 만들기(추가) → 이름(예: `music-helper`) → Google 애널리틱스는 꺼도 돼요 → 만들기
2. **로그인 켜기**: 왼쪽 메뉴 **보안(Security) → Authentication** → 시작하기 → **로그인 방법(Sign-in method)** 탭 → **이메일/비밀번호** → 사용 설정 → 저장
3. **데이터베이스 만들기**: 왼쪽 메뉴 **Firestore**(“데이터베이스 및 스토리지” 또는 “빌드” 아래) → 데이터베이스 만들기 → 위치는 **asia-northeast3 (서울)** → **프로덕션 모드** → 만들기
4. **웹 앱 등록**: 왼쪽 위 톱니바퀴 → **프로젝트 설정** → 일반 → 아래 “내 앱”에서 **웹(`</>`)** 아이콘 → 앱 닉네임 적고 등록 → 화면에 나오는 `const firebaseConfig = { ... };` 부분을 복사
5. **설정 파일 채우기**: 내가 쓸 아이디를 정해요(영어 소문자·숫자 3~20자, 예: `kimhh`). GitHub 저장소에서 `firebase-config.js` → 연필(✏️) 버튼 → `const firebaseConfig = { ... };` 부분을 4번에서 복사한 것으로 바꿔 치기 → 맨 아래 `DEV_IDS`의 `"여기에_내_아이디"`를 내 아이디로 바꾸기 → Commit changes
6. **보안 규칙 넣기**: 이 폴더의 `firestore.rules`를 메모장으로 열어 `myid`를 **내 아이디**로 바꾸고, 내용을 통째로 복사 → Firestore의 **규칙(Rules)** 탭에 붙여 넣기 → **게시**
   - 이 규칙 덕분에 서버에서도 “참가자는 주최자가 허락할 때만 고치기”, “모두의 악보 넘기기는 주최자·개발자만” 같은 약속이 지켜져요.
   - 규칙을 게시하기 전에는 프로젝트를 만들거나 볼 수 없어요.
7. **내 아이디로 가입**: 2~3분 뒤 사이트를 새로 고치면 처음 화면에 로그인·회원가입 칸이 나와요. **5번에서 정한 아이디로 가장 먼저 회원가입**하세요. 위쪽 이름 옆에 “개발자”가 보이면 성공이에요.
8. (선택) **승인된 도메인**: Authentication → 설정(Settings) → 승인된 도메인에 `내아이디.github.io`를 추가해 두면 나중에 다른 로그인 방법을 켤 때도 편해요.

- 아이디는 영어 소문자·숫자 3~20자, 비밀번호는 6자 이상이에요. 아이디는 내부에서 `아이디@music-helper.example.com` 모양의 주소로 바뀌어 저장돼요(메일은 보내지 않아요).
- `firebaseConfig`의 `apiKey`는 비밀번호가 아니라 “이 앱이 어느 Firebase를 쓰는지” 알려 주는 이름표라서 공개돼도 괜찮아요. 데이터는 6번 보안 규칙이 지켜요.
- 비밀번호를 잊은 친구가 있으면 Firebase 콘솔 → Authentication → 사용자에서 그 사람을 지우고 다시 가입하게 하면 돼요.

## 역할

| 역할 | 할 수 있는 것 |
|---|---|
| **개발자** | `DEV_IDS`와 `firestore.rules`에 적은 아이디. 모든 프로젝트를 보고 제한 없이 고쳐요. **프로젝트를 만들면서 주최자를 직접 정할 수 있어요**(나 / 아이디로 정하기 / 나중에 정하기). 모두의 악보 넘기기도 할 수 있어요. |
| **주최자** | 프로젝트를 이끄는 사람. 멤버 추가(아이디로)·역할 바꾸기·내보내기, “참가자 편집 허용”, “모두 잠그기”, 초대 코드 관리, **모두의 악보 넘기기**. 주최자가 악보를 고치면 그 악보는 마지막으로 고친 뒤 1분 동안 참가자가 건드릴 수 없어요(“조율 끝” 버튼으로 바로 풀 수 있어요). |
| **참가자** | 공유 악보 보기, 주최자가 허락하면 고치기. 주최자가 모두의 악보를 넘기는 동안에는 주최자를 따라가고, “혼자 보기”로 따로 넘길 수 있어요. |

### 개발자가 프로젝트를 만들고 주최자 정하기

1. 주최자로 정할 사람이 먼저 앱에서 **한 번 회원가입(로그인)** 해요. (그래야 아이디로 찾을 수 있어요)
2. 개발자: 처음 화면 → **악보 편집** → **프로젝트** 탭 → “새 프로젝트 만들기”에 이름을 적고, 아래 **주최자**에서 “아이디로 정하기”를 골라 그 사람의 아이디를 적은 뒤 **만들기**.
3. 주최자가 앱을 열어 두고 있었다면 그 프로젝트로 바로 들어가요(“…프로젝트에 주최자로 들어갔어요”).
4. 멤버는 초대 코드로 들어오거나, 개발자·주최자가 “사람 추가”에서 아이디로 넣어요.

## 공유되는 것

- **오선·타브 악보**: “프로젝트에 올리기”를 누른 악보. 고치면 1초 안에 멤버 모두의 화면에 바뀌어요.
- **모두의 악보 넘기기**: 주최자가 켜면, 주최자가 넘길 때 멤버 모두의 악보가 함께 넘어가요(같은 제목의 곡, 같은 쪽).
- **PDF 악보**: PDF 위의 표시(형광펜·글자·기호). PDF·사진 파일은 용량이 커서 올리지 않고, 멤버가 **같은 파일**을 각자 연결하면 보여요.

## 악보 실행

PDF나 악보 사진을 올리면 바로 넘기며 연주할 수 있어요. 곡·콘티는 이 기기에 저장돼요.

- **곡·콘티 관리**: 곡 올리기(PDF·사진), 내 악보함에서 가져오기, 곡마다 제목·키·빠르기(BPM)·박 수·곡 길이(자동 스크롤용). **콘티**(세트리스트)를 여러 개 만들고 곡 순서를 ▲▼로 바꿔요. 곡의 마지막 쪽에서 넘기면 다음 곡 첫 쪽으로 넘어가요.
- **넘기기**: 악보 **오른쪽**(70%)을 누르면 다음, **왼쪽**(30%)을 누르면 이전. 옆으로 밀어도 돼요. 블루투스 페이지 넘김 페달·키보드: `→`·`PageDown`·`Space` 다음, `←`·`PageUp` 이전, `Home` 처음.
- **보기**: `한 쪽` · `반 쪽 넘김`(위쪽 반이 먼저 다음 쪽으로 바뀌어서, 아래 줄을 보면서 미리 다음 쪽을 봐요) · `두 쪽`(가로 화면) · `이어 보기`(위아래로 밀기, **자동 스크롤**: 곡 길이에 맞춰 천천히 내려가요)
- **▣ 구간 표시** (지금 하는 부분이 잘 보이게): 구간(보통 악보 한 줄)을 정해 두면 `다음`을 누를 때마다 다음 구간이 **반짝**이고, 그 쪽의 마지막 구간이 끝나면 쪽이 넘어가요(반 쪽 넘김에서는 위쪽 반부터 먼저).
  - 표시 방법: **테두리만 반짝**(구간 둘레 선만) · **가사만 반짝**(오선 아래 가사 글자만 주황색으로 반짝, 가사가 없는 줄은 테두리로) · **형광펜** · **끄기**
  - 구간 만들기: **악보 줄 자동으로 나누기**(옅은 회색 오선도 찾아요), 또는 악보 위를 끌어서 네모. 구간을 눌러 고른 뒤 지울 수 있어요. 곡마다 저장돼요.
  - 점프 링크를 누르면 도착점의 구간으로, 주최자가 넘기면 멤버도 같은 구간으로 옮겨 가요.
- **악보 확대**: 두 손가락으로 벌리거나 오므려요(컴퓨터는 Ctrl + 마우스 휠, 키보드 `+` `-` `0`). 위의 `− 쪽 맞춤 +` 버튼, **폭 맞춤**(쪽 가로를 화면에 꽉 차게), **여백 자르기**(악보 둘레 흰 여백을 잘라 크게). 확대는 곡마다 기억해요. 확대해서 쪽이 화면보다 크면 `다음`을 누를 때 먼저 쪽 안에서 아래로 내려가고, 맨 아래에 닿으면 다음 쪽으로 넘어가요. 크게 보기에서는 왼쪽 위 `−` `+`로 확대해요.
- **↪ 점프 링크**: 반복표·D.S.·Coda 자리(출발점)를 누르고, 돌아갈 곳(도착점)을 누르면 링크가 생겨요. 연주할 때 파란 ↪ 점을 누르면 바로 그 쪽으로 넘어가요.
- **♩ 메트로놈**: 곡의 빠르기·박 수로 딸깍, **카운트인**(1마디 세고 멈춤), **화면 깜빡임**(첫 박은 빨강, 나머지 노랑 테두리) — 이어폰 없이도 박을 봐요.
- **♫ 반주**: 곡마다 반주 음원(MR) 하나. 재생·멈춤, **A-B 반복**(연습할 구간만 반복).
- **🔒 공연 잠금**: 넘기기만 되고 다른 버튼은 숨겨요(실수로 누르지 않게). 아래 🔒을 **길게 누르면** 풀려요.
- **밤 모드**: 어두운 무대에서 악보를 검은 바탕·흰 글씨로 바꿔요.
- **크게 보기**: 악보와 넘김 막대만 남기고, 화면이 꺼지지 않게 해 둬요(지원하는 브라우저에서).
- **PDF 악보 탭**에서 고친 표시(가리기·음표·코드·형광펜)도 그대로 보여요. PDF 탭의 “악보 실행으로 열기”로 바로 와요.
- **프로젝트에서**
  - 주최자·개발자: `각자 넘기기 | 모두의 악보 넘기기`에서 **모두의 악보 넘기기**를 켜면, 내가 넘길 때 멤버들의 악보가 **같은 제목의 곡, 같은 쪽**으로 넘어가요. (악보 파일은 각자 기기에 같은 제목으로 넣어 둬요)
  - 멤버는 “혼자 보기”로 따로 넘기고, “다시 따라가기”로 돌아와요.

## 내 악보함 (처음 화면 아래)

- 오선·타브 악보(고치면 자동 저장), PDF·사진 파일이 모여요. 위 칸으로 종류별로 볼 수 있어요.
- `열기`·`악보 실행` 버튼, `⋯`에서 이름 바꾸기·복사·프로젝트에 올리기·지우기.
- 프로젝트에 들어가 있으면 아래에 그 프로젝트의 공유 악보도 보여요.
- 이 기기(브라우저)에만 저장돼요. 다른 기기에서 쓰려면 프로젝트에 올려 주세요.

## Claude 화면(아티팩트)에서 쓸 때

Claude 안에서 열면 Firebase 없이 **Claude 계정**으로 로그인되고, 데이터는 Claude가 그 아티팩트에 보관해요.
아티팩트를 만든 사람이 개발자예요. 친구와 함께 쓰려면 아티팩트의 공유 메뉴에서 친구를 초대해야 해요(같은 조직 사람은 “참여자(Contributor)” 이상, 조직 밖 사람은 이메일로 “편집자(Editor)” 초대가 필요해요).
주최자를 정할 때는 “사람 고르기”에서 이 아티팩트를 한 번이라도 연 사람 중에 골라요.

`index.html`의 `?v=` 숫자들, `sw.js`의 `mh-score-v` 숫자, `version.json`의 `"version"`을 하나씩 올려서 다시 올리면 돼요. (Claude에게 “새 버전으로 만들어 줘”라고 하면 한꺼번에 올려 줘요)

## 갤럭시 탭 앱 자동 업데이트 (앱으로 만든 뒤)

갤탭 앱은 인터넷에 연결될 때 이 사이트의 `version.json`을 보고, 숫자가 앱보다 높으면 새 화면 코드를 받아 둬요(“새 버전을 받아 뒀어요 · 지금 적용”).
- 그래서 **새 버전 파일을 GitHub에 올리기만 하면** 갤탭 앱도 알아서 바뀌어요. `version.json`을 꼭 같이 올려요.
- `version.json`에는 파일마다 지문(SHA-256)이 들어 있어서, 받은 파일이 망가졌으면 적용하지 않아요. 그래서 **다른 파일을 GitHub에서 직접 고치면 앱 업데이트가 멈춰요**(웹 사이트는 그대로 돼요). `firebase-config.js`만은 지문을 확인하지 않아서 GitHub에서 직접 고쳐도 돼요.
- 파일을 직접 고친 뒤 앱에도 보내고 싶으면 Claude에게 새 `version.json`을 만들어 달라고 하면 돼요.

- 악보 넘기기에서 “왼쪽을 누르면 이전”의 넓이 바꾸기: `stage.js`의 `stgBindView` 안 `0.3` (30%)
- 공연 잠금을 푸는 길게 누르기 시간: `stage.js`의 `stgUnlockBind` 안 `800` (0.8초)
- 구간 표시 색: `style.css`의 `--sthl`, “가사만 반짝”의 글자 색: `stage.js`의 `stgRegInk` 안 `col` (주황 232, 89, 12)
- 구간 표시 방법 목록·이름: `stage.js`의 `STG_HLS`
- 확대 단계·최대 배율: `stage.js`의 `STG_ZOOMS`, `STG_ZMAX` (기본 최대 4배)
- 화면 깜빡임 색: `style.css`의 `--stbeat`(박), `--stbeat1`(첫 박)
- 주최자 잠금 시간 바꾸기: `collab.js`의 `LOCK_MS` (1분 = 60000). `firestore.rules`의 `duration.value(60, 's')`도 같이 바꿔요.
- 형광펜 표시 종류 추가: `score-edit.js`의 `MARK_TYPES`에 한 줄 추가 (PDF 악보 탭에도 같이 나와요)

## 개발자 코드

처음 화면 아래 **“개발자 코드로 들어가기”**에 개발자 코드를 넣으면 바로 개발자로 들어가요.
- 로그인 서버(Firebase)를 켰다면: `DEV_IDS`의 첫 번째 아이디로, 개발자 코드를 비밀번호로 써서 로그인해요. 그 계정이 아직 없으면 자동으로 만들어요.
- 로그인 서버가 없으면(혼자 쓰기): 이 기기에서 개발자 모드로 들어가요. 위쪽 “개발자 모드 끄기”로 끌 수 있어요.
- 앱 코드에는 개발자 코드 자체가 아니라 SHA-256 값(`collab.js`의 `DEV_CODE_HASH`)만 들어 있어요.
- **코드 바꾸기:** 새 코드의 SHA-256 값을 구해 `DEV_CODE_HASH`를 바꿔요. (예: 크롬 주소창 옆 개발자 도구 콘솔에서 `devCodeHash('새코드').then(console.log)`) Firebase를 쓴다면 개발자 계정의 비밀번호도 새 코드로 바꿔야 해요.
